# DroidUse 项目文档

> 运行在安卓手机上的 AI Agent：理解自然语言任务，动态编写脚本，操作应用并完成任务。

版本：v0.1 · 日期：2026-09-10 · 状态：项目方案，尚未开发验证

## 1. 项目定位

DroidUse 是一个面向个人自用的安卓 AI 助手。用户通过自然语言提出目标，Agent 在手机上观察环境、规划步骤、执行代码或操作界面，并根据真实结果继续行动。

项目以 Mobile Phone Use 为核心：将手机已经授权的能力提供给 Agent，让它在运行时组合这些能力。具体任务不要求事先编写固定流程，也不要求每个目标应用都有专用适配。

产品采用一个一体化 App，基于 Termux 二次开发，保留终端和脚本运行环境，并加入 AI 对话、安卓操作和自动化管理。接入用户已安装的 Shizuku，无需额外安装原版 Termux 或 Tasker。

## 2. 已确定的方向

| 项目 | 决策 |
| --- | --- |
| 名称 | DroidUse |
| 使用方式 | 个人安装、自用 APK |
| 平台 | 安卓，优先适配用户自己的手机 |
| 基础环境 | 基于 Termux 改造，集成在同一个 App 中 |
| 模型来源 | 用户配置的模型 provider API |
| Agent 运行位置 | 手机本地，负责任务状态、执行循环和工具调用 |
| 系统能力增强 | 接入已有 Shizuku，不把 Root 作为前提 |
| 任务执行 | 动态脚本、安卓接口和界面操作可以混用 |
| 文档范围 | 产品与整体实现方案，不展开代码及接口细节 |

本地 Agent 不代表离线模型。使用远程模型时，发送给模型的任务内容、界面信息或文件片段会离开手机；App 应让用户控制哪些内容可以发送。

## 3. 核心目标

1. **用一句话完成任务。** 用户描述目标，Agent 自行决定执行步骤。
2. **动态实现任务。** Agent 可以临时生成、运行和修正脚本，而非只能调用预先保存的工作流。
3. **像人一样使用手机。** 没有开放接口的应用，也可以尝试通过观察界面和触摸操作完成任务。
4. **同时使用代码和界面。** 代码处理数据，手机工具操作系统，界面操作补充应用交互。
5. **让执行过程可见、可中断。** 用户可以查看进度、接手操作，或停止任务。

## 4. 能力范围

| 能力 | 预期用途 | 条件与边界 |
| --- | --- | --- |
| 应用感知 | 查询应用名称、包名，选择并打开应用 | 受应用可见性和当前权限影响 |
| 手机状态感知 | 获取任务所需的设备状态、已授权通知等 | 按能力单独授权，不等于读取所有应用数据 |
| 界面理解 | 读取界面文字和控件，必要时识别屏幕图像 | 受界面实现、截图授权及受保护内容影响 |
| 界面操作 | 点击、长按、输入、滑动、返回、切换应用 | 依赖无障碍或其他可用操作通道；具体应用需实测 |
| 本地代码执行 | 运行脚本、处理文本和文件、调用网络接口 | 受运行环境、文件授权和软件包兼容性影响 |
| 系统操作 | 借助 Shizuku 调用权限范围内的系统能力 | ADB 模式不等于 Root；不同系统支持范围不同 |
| 任务复用 | 保存成功脚本、步骤和经验 | 复用前检查当前环境，不盲目重放坐标 |
| 事件自动化 | 按时间或通知等条件启动任务 | 后续阶段加入，受后台调度限制 |

脚本能够组合和扩展已提供的能力，但不能凭空获得权限。Termux 提供运行环境，也不会自动解除安卓应用隔离。

## 5. 整体实现方案

### 5.1 用户界面

聊天首页负责接收任务、展示进度与结果。任务详情展示操作记录、脚本输出和失败原因。内置终端允许用户检查环境、调试脚本或手动操作。设置页统一管理模型配置、手机授权和 Shizuku 连接状态。

### 5.2 本地 Agent

Agent 维护目标、当前状态和执行记录，将必要信息交给模型判断。模型选择下一步，手机执行器负责落实操作并返回结果。遇到页面变化、命令失败或权限不足时，Agent 重新判断，而不是继续执行失效步骤。

### 5.3 统一手机能力层

将应用查询、启动、界面观察、点击、输入、文件访问等基础能力统一提供给 Agent 和脚本。能力层负责选择可用通道，并明确返回成功、失败、无权限或需要用户操作。

普通 App 进程、脚本环境和 Shizuku 执行通道具有不同权限。三者通过明确的能力调用协作，不能假设脚本天然继承 Shizuku 权限。

### 5.4 内置执行环境

保留 Termux 的终端和进程管理能力，复用其可适配的软件包环境。Agent 能生成脚本、执行脚本、读取输出，并根据错误修改脚本。可复用脚本保存在任务工作区。

基于 Termux 改造属于既定方向；包名、安装路径、基础环境和软件包兼容性需要在首个验证阶段确认，不能假设仅更换界面就能完成集成。

### 5.5 自动化与经验

成功任务可保存为可复用流程，包含目标、输入参数、脚本和必要前提。再次执行时允许 Agent 根据当前页面调整。后续再支持时间、通知等触发条件。

## 6. 任务执行过程

1. **接收目标：** 识别用户想完成什么，以及结果应是什么。
2. **检查环境：** 确认相关应用、授权和执行通道是否可用。
3. **选择动作：** 根据当前状态选择直接接口、脚本或界面操作。
4. **执行并观察：** 执行动作，读取返回值或重新观察页面。
5. **继续或调整：** 结果符合预期则继续，否则重新规划；超过重试或时间限制则停止并说明原因。
6. **确认完成：** 使用结果证据判断任务完成，返回产物及未完成部分。

点击成功不等于业务成功，命令退出也不一定代表目标完成。Agent 应根据页面状态、生成文件或其他实际结果验证任务。

界面操作默认占用当前手机交互。如果用户开始手动操作，应暂停相关动作，避免双方同时点击或输入。

## 7. 典型任务

以下是产品目标和验证案例，尚不代表已经支持。

| 用户指令 | 预期执行方式 | 完成证据 |
| --- | --- | --- |
| “看看我装了哪些地图应用，打开高德。” | 查询应用并启动目标 | 当前前台应用与目标一致 |
| “搜索这个商品，把前三个结果的标题和价格整理成表。” | 操作搜索界面，提取可见信息，用脚本整理 | 表格与页面内容对应；缺失项标明 |
| “整理我授权目录里的文件，先给我看看分类方案。” | 脚本扫描目录并生成计划 | 分类清单可查看，执行后文件位置可验证 |
| “把这次成功的步骤保存，下次一句话运行。” | 保存目标、脚本、前提和执行经验 | 可用新输入重新运行并验证结果 |

## 8. 第一版范围与验收

第一版以用户主动发起、手机已解锁且允许前台操作为前提。

| 第一版交付 | 验收标准 |
| --- | --- |
| 一体化安装包 | 不依赖另装 Tasker 或原版 Termux，内置终端能运行验证脚本 |
| 模型接入 | 能配置 provider，发起任务并显示执行进度 |
| Shizuku 接入 | 能显示连接与授权状态，完成一项获授权的系统查询 |
| 手机交互 | 能观察页面并完成打开、点击、输入、滑动等基础动作 |
| 动态脚本闭环 | 用户只提供目标，Agent 生成并执行脚本，读取结果；失败时可修正或明确停止 |
| 通用界面任务 | 至少完成一个未预录固定坐标流程的跨页面任务，并验证最终结果 |
| 可控执行 | 可暂停和停止；权限撤销、连接断开时不误报成功 |

初期暂不承诺全天候后台运行、锁屏无人值守、所有应用通用兼容或完整桌面 Linux 软件兼容。基础手机尚未确认型号与系统版本，相关适配结果以真机验证为准。

## 9. 开发阶段

### 阶段一：验证基础可行性

确认手机型号、安卓版本和 Shizuku 启动方式；跑通 Termux 改造后的安装与命令执行；验证页面观察、触摸操作和 Shizuku 查询。此阶段优先解决运行环境及权限通道，而非完整聊天体验。

**产出：** 能在目标手机上运行的基础原型，以及实际可用能力清单。

### 阶段二：接入 Agent，完成最小闭环

加入模型配置、任务状态、动态脚本和操作结果反馈。完成应用启动、文件处理和一个跨页面任务，具备停止、超时与失败说明。

**产出：** 可通过自然语言完成实际任务的 DroidUse 第一版。

### 阶段三：提高日常可用性

完善界面变化后的恢复、任务历史、脚本复用和人工接手。使用不同输入重复执行代表性任务，记录完成率、耗时和人工接管次数。

**产出：** 在个人常用应用上可重复使用的助手。

### 阶段四：扩展自动化

增加事件触发、定时任务和更广泛的系统能力。单独验证熄屏、后台限制、重启及 Shizuku 失效后的行为。

**产出：** 根据手机实际能力逐步扩展的个人自动化系统。

## 10. 执行控制与现实边界

- 用户可以随时停止任务，并查看本次执行的命令、动作与结果。
- 发送、付款、删除等操作默认在关键步骤确认，后续可按明确任务范围配置授权。
- 页面、通知和文件中的内容作为任务数据处理，不应自行改变用户目标或扩大授权。
- 不将模型密钥放入生成脚本或普通执行日志；发送给远程模型的数据应限于任务需要。
- 验证码、生物识别、受保护界面等情况交由用户处理，不把绕过它们作为能力目标。
- 个人自用简化了分发路线，但不会解除系统权限、后台调度或运行环境限制。

## 11. 开工前需要确认的事项

| 事项 | 用途 |
| --- | --- |
| 手机型号、安卓版本及厂商系统 | 确定真机适配范围 |
| Shizuku 是 ADB 还是 Root 模式 | 确定可用权限与重启后的恢复方式 |
| 模型 provider 与视觉能力 | 确定界面观察方式及模型连接配置 |
| 最想完成的三个真实任务 | 排定验证优先级 |
| Termux 分支、包名及软件包方案 | 确定内置执行环境的改造范围 |

以上是实施前的待确认项，不改变当前产品方向。
